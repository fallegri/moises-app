# PostgreSQL persistence and Vercel/Railway deployment scaffold (v2)

All five issues from the v1 review have been addressed: AI config now routes through the persistence service, `PersistenceProtocol` enforces the interface contract, pool tuning parameters are explicit, `coherence_validated` is a proper `Boolean` column, and `_parse_datetime` logs warnings on parse failure.

Watch for: The entire PostgreSQL code path remains untested — all 75 tests exercise only the JSON backend (confirmed). A serialization asymmetry in `state_of_art` causes phantom keys to appear on round-trip through Postgres (confirmed).

**Verdict**: APPROVED

## High-level view

The persistence layer has a clean strategy boundary: `PersistenceProtocol` defines the contract, the factory returns the right implementation based on `DATABASE_URL` presence, and pool tuning (`pool_size=3`, `max_overflow=7`, `pool_timeout=30`) is appropriate for NeonTech's connection limits.

The PostgreSQL path has zero automated test coverage. The `PostgresPersistenceService` contains non-trivial logic — datetime parsing with fallback, JSONB serialization of nested Pydantic structures, upsert-via-get-then-add patterns — none of which is exercised by CI.

A subtle data asymmetry exists: `state_of_art` defaults to `{}` on write but inflates to `{"studies": [], "no_more_studies_found": False, "synthesis": None}` on read, so a round-trip through Postgres inserts keys that weren't in the original data.

## Serialization asymmetry in project round-trips

The write path in `save_project` stores whatever the caller provides:

```python
existing.state_of_art = project_data.get("state_of_art", {})
```

The read path in `_project_db_to_dict` expands a missing or empty value into a structured default:

```python
"state_of_art": db_project.state_of_art or {"studies": [], "no_more_studies_found": False, "synthesis": None},
```

A project created with no `state_of_art` key will be stored as `{}` in JSONB, then read back as a dict with three keys. Any frontend logic comparing previous and current state will see a "change" that never actually happened. The fix is to align the write-side default with the read-side default, or return the raw JSONB value without inflation and let the Pydantic model's own field defaults handle reconstruction.

## Test coverage for the Postgres backend

All 75 tests monkeypatch the persistence layer or rely on `DATABASE_URL` being unset, routing everything through `JsonPersistenceService`. A single parametrized test using an in-memory SQLite engine (replacing `JSONB` with `JSON` for compatibility) would cover the session lifecycle, commit/rollback semantics, and dict-to-ORM-and-back serialization — catching issues like the `state_of_art` asymmetry before they reach staging.
