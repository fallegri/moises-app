# Collection-suggestions list after phase-1 problem analysis (v1)

Phase 2 (INSTRUMENT_SUGGESTION) asked users to "report the data collected" without ever telling them what to collect. This change (Option A) has the phase-1 model append a section titled "Informacion que debes recopilar" (markdown bullets) to its analysis, exposes the whole response as `collection_suggestions` on the phase result, and renders it in the frontend under a dedicated heading right after the problem analysis. The graceful-degradation path is preserved: on an unconfigured/failed AI the suggestions are normalized to `''` and the block is hidden behind the existing amber advisory. The user's core ask — a readable list of what to gather for the next phase — is satisfied, and the guidance survives reload because it comes from the persisted `phase_result`.

Watch for: the new block renders the **entire** AI response (problem statement + justification + the collection section), not just the recollection list, so the full analysis is shown twice on screen — once in the green "identified problem" box and again under the "Informacion que debes recopilar" heading (confirmed). The heading therefore mislabels its content.

**Verdict**: NEEDS_CHANGES

## High-level view

The backend aliases the recollection guidance to the same string as the identified problem: `identified_problem`, `collection_suggestions`, and `ai_response` are all set to the single `ai_response` returned by `analyze_problem`. There is no server-side split of the "Informacion que debes recopilar" section from the problem analysis, so `collection_suggestions` is the whole document, not just the list.

The frontend renders that whole document twice. The pre-existing green block prints `identified_problem` as pre-wrapped text (including the collection section), and the new block prints `collection_suggestions` — the same text — as markdown under a heading that promises only the recollection list. The list does appear and is readable, which meets the user's request, but it arrives duplicated and mislabeled.

Degradation is handled symmetrically: when the AI is unconfigured or errors, `collection_suggestions` is forced to `''` alongside `ai_response`, and the render gate (`collection_suggestions && !hasAiIssue`) keeps the block hidden while the amber advisory explains the situation.

The render also depends on the model producing a section titled exactly "Informacion que debes recopilar". If the model renames or omits it, there is no server-side validation or fallback — the heading still renders over whatever text came back.

## `collection_suggestions` is an alias of the full response, not the list

In `process_input`'s PROBLEM_IDENTIFICATION branch the result is built as:

```python
result = {
    "identified_problem": ai_response,
    "collection_suggestions": ai_response,
    "saved_text": user_input,
}
```

and `ai_response` later also becomes the shared `result["ai_response"]`. All three fields hold the same markdown string — the problem statement, its justification, and the appended "Informacion que debes recopilar" bullets in one blob. Nothing ever isolates the list.

The consequence is visible on screen. The green submit-confirmation block renders `identifiedProblem` as `whitespace-pre-wrap` text:

```tsx
{identifiedProblem && (
  <p className="text-sm text-slate-700 whitespace-pre-wrap">{identifiedProblem}</p>
)}
```

and immediately below, the new block renders `collectionSuggestions` — the same string — through `AIResponse` (ReactMarkdown, wrapped in a card titled "Respuesta del Asistente"):

```tsx
{phase === 'problem_identification' && collectionSuggestions && !hasAiIssue && (
  <div className="space-y-2">
    <h4 ...>Informacion que debes recopilar para la siguiente fase</h4>
    <AIResponse content={collectionSuggestions} />
  </div>
)}
```

So the reader sees the problem analysis in full, then a heading claiming "Informacion que debes recopilar para la siguiente fase," and under it the same problem analysis again (now markdown-formatted, nested inside a second "Respuesta del Asistente" card header). The requested list is present at the tail of that second render, but buried under a repeat of the analysis and mislabeled by the heading.

Separate the concerns: split on the "Informacion que debes recopilar" marker server-side (put only the problem in `identified_problem`, only the bullets in `collection_suggestions`), or do the same split in the component before rendering. Splitting server-side keeps the two consumers honest and avoids shipping the same payload three times over the wire.

## Prompt-section contract has no fallback

The render and the intended split both hinge on the model emitting a section titled exactly "Informacion que debes recopilar" — the prompt instructs it ("titulada exactamente") and `test_ai_service.py` locks the phrase into the prompt text. But there is no runtime check that the returned text actually contains that section. Today, because `collection_suggestions` is the whole response, the block always renders *something* whenever the AI succeeds; once the content is split on the marker (the fix above), a model that renames or drops the section yields an empty list — or, if the split is naive, leaves the heading over unrelated prose. Gating the block on the marker's presence would make the feature robust to model drift. (likely — the current alias masks it, but any split implementation inherits this dependency.)

## Degradation and test coverage

The degradation normalization mirrors `ai_response`:

```python
if "collection_suggestions" in result and (ai_unconfigured or ai_error is not None):
    result["collection_suggestions"] = ""
```

Combined with the render gate `collection_suggestions && !hasAiIssue`, a degraded AI hides the suggestions block and shows only the amber advisory. Because the field lives in `phase_data` and `/status` returns it as `phase_result`, the guidance is rebuilt on reload without re-submitting.

Backend tests assert the populated field, the two degraded paths, and persistence into `phase_data`; frontend tests assert the heading/bullets render on success and disappear on `ai_error`. Not tested: the double-render behavior — no test asserts the problem text is *not* repeated in the suggestions block, which is why the duplication slipped through — and the missing-section case where the AI omits "Informacion que debes recopilar".
