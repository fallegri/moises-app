# AI research assistant with 12-phase workflow (v3)

All 14 issues from v1 and v2 have been addressed: URL routing aligned under `/api/`, coherence validation defaults to false, persistence covers projects, workflows, and now documents, the knowledge upload appends to the in-memory base, API key validation is lazy, content-type is JSON, state-of-art endpoints are wired from the frontend, phase IDs match the backend enum, `WorkflowStatus` type matches the backend response shape, search results use `{ filename, heading, content, score }`, Docker has a named volume for storage, and the README documents the single-worker constraint.

Watch for: the `generateDocument` frontend call sends no request body, but the backend requires a `content` field — the call will 422 every time (confirmed). The `CoherenceValidation` component renders `score`, `issues`, and `suggestions` fields that the backend never returns, so the validation UI will always show 0% and empty lists (confirmed). The `VariableMatrix` component is entirely local state with no backend persistence or API, so variable data entered by the user is lost on page refresh (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

Document generation is unreachable from the UI. The frontend `generateDocument` function sends an empty POST body to an endpoint that declares `content: str` as a required Pydantic field. FastAPI will reject every request with a 422 Validation Error. This is a blocking integration bug for the document download feature.

The coherence validation UI and backend speak different languages. The backend returns `{ is_coherent: bool, message: str }`, but the component renders a progress bar from `score` (undefined), iterates `issues[]` (undefined), and shows `suggestions[]` (undefined). The validation button will work — the mutation fires and data returns — but the visual feedback is meaningless: an empty card with 0% and no text.

The `VariableMatrix` component — the conceptualization-of-variables matrix required for the methodological framework phase — holds all data in React local state. No API endpoint exists to persist or retrieve variables. A page refresh or navigation away discards the user's work. This parallels the v2 issue with `StateOfArtMatrix` (which was fixed), but the variable matrix was missed.

The project listing renders `project.progress` and `project.description`, but neither field exists in the backend response model. The progress bar on the Home page will always read `undefined%` (rendered as empty or NaN depending on the browser's handling of `style={{ width: 'undefined%' }}`), and the description line will always be blank.

1. **Document generation 422** — Frontend `generateDocument` sends no body; backend requires `content: str`. Either send chapter content from frontend state (the `phase_data` accumulated during the workflow), or make `content` optional on the backend and derive it from the project's persisted data.
2. **Coherence validation response shape mismatch** — Frontend `ValidationResult` expects `{ is_valid, score, issues, suggestions }`; backend returns `{ phase, is_coherent, message }`. 3. **VariableMatrix has no backend persistence** — Variables entered in the methodological framework phase are stored only in React state. Add a backend endpoint (similar to the state-of-art `add-study` pattern) or integrate variable storage into the `submit-input` flow.
4. **Home page expects `progress` and `description` on project** — The backend `ResearchProject` model lacks both fields. Either add them (compute `progress` from `completed_phases.length / 12`, accept `description` in `CreateProjectRequest`) or remove the references in the frontend.

## Document generation sends no body

The frontend client function:

```typescript
export async function generateDocument(projectId: string, chapter: string): Promise<{ message: string }> {
  const response = await api.post(`/api/documents/${projectId}/generate/${chapter}`)
  return response.data
}
```

The backend endpoint:

```python
class GenerateDocumentRequest(BaseModel):
    content: str
    author: Optional[str] = None
    references: Optional[list[str]] = None

@router.post("/{project_id}/generate/{chapter}")
async def generate_document(project_id: str, chapter: str, request: GenerateDocumentRequest):
```

`content` is a required field with no default. Axios sends `undefined` as the body (no second argument), which arrives as an empty body. Pydantic raises a validation error: `field required`. The `DocumentDownload` component's "Generar" button will fail silently (the catch block does nothing visible) or throw to the error boundary if one exists.

The fix is either: (a) the frontend passes the chapter content accumulated in `workflow.phase_data` during the workflow, or (b) the backend reads the project's phase data from persistence and builds the content internally, making `content` optional.

## Coherence validation UI renders undefined fields

The backend returns:

```python
return {
    "phase": state.current_phase.value,
    "is_coherent": validation["is_coherent"],
    "message": validation["message"],
}
```

The frontend `ValidationResult` type and `CoherenceValidation` component expect:

```typescript
interface ValidationResult {
  is_valid: boolean   // backend sends is_coherent
  score: number       // backend doesn't send this
  issues: string[]    // backend doesn't send this
  suggestions: string[] // backend doesn't send this
}
```

The component renders `result.score` in a progress bar width calculation, iterates `result.issues.length` (which will throw if `issues` is undefined — `Cannot read properties of undefined (reading 'length')`), and iterates `result.suggestions.length`. This will either crash the component or render empty sections depending on whether optional chaining is added by the build.

The mapping is: rename `is_coherent` to `is_valid` in the type (or map it in the API client), derive `score` from a heuristic (100 if coherent, 0 otherwise), and parse structured feedback from `message` into `issues`/`suggestions` arrays — or simplify the component to just show `is_coherent` and `message`.

## VariableMatrix is client-only

The `StateOfArtMatrix` was wired to `addStudy` and `setNoMoreStudies` backend endpoints in the v2 fix. The `VariableMatrix` component follows the same local-state-only pattern that was a problem before:

```typescript
export default function VariableMatrix() {
  const [variables, setVariables] = useState<VariableEntry[]>([])
  // ... no API calls anywhere in this component
}
```

No backend endpoint exists at `/api/workflow/{id}/variables/add` or similar. The `MethodologicalFramework` model on the backend has a `variable_matrix: VariableConceptualizationMatrix` field, but nothing writes to it. A user filling in variables during the methodological framework phase will lose all data on refresh. Since the methodological framework phase is the 11th of 12, this affects users near the end of their research project.

## Project list renders missing fields

`Home.tsx` renders:

```tsx
<p className="text-xs text-slate-500 mt-0.5 truncate">{project.description}</p>
// ...
style={{ width: `${project.progress}%` }}
<span className="text-xs text-slate-400">{project.progress}%</span>
```

The backend `ResearchProject` response model contains neither `description` nor `progress`. The `CreateProjectRequest` on the backend only accepts `title: Optional[str]`. The frontend sends `description` in the create body, but Pydantic's default config silently drops unknown fields. Every project card will show an empty description and a broken progress indicator.
